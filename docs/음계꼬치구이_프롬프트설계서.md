# 음계 꼬치구이 — 단계별 프롬프트 설계서 v1.0

작성: 2026-11-12 · 기준 문서: `음계꼬치구이_기획서.md` v1.0
쓰는 도구: Claude Code(맥북), GitHub, Vercel

## 0. 사용법

### 0-1. 이 문서로 하는 일

단계마다 프롬프트 하나를 Claude Code에 붙여 넣어 앱을 조금씩 만든다. 단계는 앞 단계가 끝나야 다음으로 넘어갈 수 있게 짰다.

| 단계 | 만드는 것 | 끝나면 되는 것 |
|---|---|---|
| 1 | 프로젝트 뼈대 | 빈 화면이 뜨고 검사 명령이 통과한다 |
| 2 | 규칙 엔진 | 검증 자료 5,277건과 일치한다 |
| 3 | 주문 상태와 문구 | 화면 없이 입문 대본이 테스트로 돌아간다 |
| 4 | 악보 | 26개 음계의 음표와 조표가 맞게 그려진다 |
| 5 | 꼬치와 재료 건반 | 시제품과 같은 모양의 부품이 나온다 |
| 6 | 소리 | 건반을 누르면 음이 난다 |
| 7 | 배우기 주문 화면 | 음계 하나를 꽂고 굽는다 |
| 8 | 입문과 정리 | 처음 여는 사람이 C → F → 비교까지 간다 |
| 9 | 저장, 홈, 메뉴판 | 별이 남고 음계가 차례로 열린다 |
| 10 | 도전 주문 | 굽기 때 한 번에 판정한다 |
| 11 | 빈자리 채우기, 고쳐 굽기 | 응용 주문 두 가지 |
| 12 | 이름표 달기, 쌍둥이, 연결 안내 | 별 3개까지 받을 수 있다 |
| 13 | 설정, 선생님 설정, 도움말 | 수업에서 범위를 고른다 |
| 14 | 가로 배치 | 태블릿과 전자칠판에서 펼쳐 보인다 |
| 15 | 전체 점검 | 기획서 13장의 기준을 모두 통과한다 |
| 16 | 배포와 실제 기기 확인 | 주소로 접속한다 |
| 17(선택) | 낱개 그림으로 바꾸기 | 임시 그림이 준비한 그림으로 바뀐다 |
| 18(선택) | 오프라인 설치 | 인터넷 없이도 열린다 |

8단계까지 마치면 시제품과 같은 범위가 실제 앱으로 돌아간다. 12단계까지가 게임의 전부이고, 13~16단계는 수업에서 쓰기 위한 마무리다.

### 0-2. 한 단계를 진행하는 순서

1. Claude Code에서 새 대화를 시작한다(이전 단계의 대화를 이어 쓰지 않는다).
2. 그 단계의 "프롬프트" 칸 안의 글을 전부 복사해 붙여 넣는다.
3. Claude Code가 계획을 보여 주면 읽고, 그 단계의 "하지 않는 것"을 넘지 않았는지 본 뒤 진행하라고 답한다.
4. 끝났다고 보고하면 "완료 기준"의 명령이 통과했는지 보고서에서 확인한다.
5. "직접 확인할 것"을 폰이나 브라우저에서 해 본다.
6. 이상이 없으면 "이 단계를 커밋해 줘"라고 한다. 이상이 있으면 본 것을 그대로 적어 고쳐 달라고 한다.

막히면 5장의 도움 프롬프트를 쓴다.

### 0-3. 시작하기 전에 (직접 할 일)

1. 맥북에서 새 폴더를 만든다. 이름은 `scale-skewer`.
2. 그 안에 `docs` 폴더를 만들고 받은 파일을 넣는다.

```text
scale-skewer/
  docs/
    음계꼬치구이_기획서.md
    음계꼬치구이_프롬프트설계서.md
    음계꼬치구이_그림제작목록.md
    reference/                      (받은 묶음 파일을 풀어 넣는다)
      skewer_golden_v1.json
      engine.reference.ts
      check-golden.mts
      gen_golden.py
      scale-skewer-prototype.html
      staff_glyphs.json
      Bravura-OFL.txt
```

3. 터미널에서 그 폴더로 가서 Claude Code를 실행한다.
4. 1단계의 프롬프트를 붙여 넣는다.

GitHub 저장소와 Vercel 연결은 16단계에서 한다. 그 전까지는 맥북 안에서만 작업한다.

## 1. CLAUDE.md 초안

1단계에서 Claude Code가 아래 내용을 그대로 `CLAUDE.md`로 저장한다. 이 파일은 Claude Code가 대화를 시작할 때마다 읽는 작업 지침이다.

````markdown
# 음계 꼬치구이 — 작업 지침

## 이 프로젝트
초등 5~6학년 음악 수업용 음계 학습 게임 웹앱. 서버와 로그인이 없다.
기준 문서는 docs/음계꼬치구이_기획서.md 다(규칙 R-xx, 문구 T-xx). 문서와 코드가 다르면 문서가 기준이다.
문서가 틀렸다고 생각되면 고치지 말고 먼저 알린다.

## 함께 일하는 사람
만드는 사람은 비개발자다.
- 한국어로, 결론부터, 쉬운 말로 보고한다. 전문용어는 필요할 때만 짧게 풀어 쓴다.
- 결정이 필요하면 무엇을 정해야 하는지, 선택지와 추천, 영향을 알린다.
- 직접 해야 할 일은 어디에서 무엇을 누르는지 순서대로 안내한다.
- 확인한 것과 확인하지 못한 것을 나눠서 말한다.

## 지킬 것
1. src/game/ 에는 순수 함수만 둔다. React, DOM, 시간 함수, Math.random 을 쓰지 않는다.
2. 엔진은 docs/reference/skewer_golden_v1.json 과 모두 일치해야 한다.
3. docs/reference/ 의 파일은 읽기만 하고 고치지 않는다.
4. 화면에서 음 이름이나 정답을 따로 계산하지 않는다. 엔진이 돌려준 값만 그린다.
5. 안내 문구는 src/lib/strings.ts 에만 둔다(T-xx). 음 이름 넣기와 조사는 R-60~R-62 를 따른다.
6. 그림은 src/art/manifest.ts 로만 부른다.
7. 색과 크기는 src/lib/tokens.ts 와 CSS 변수로 쓴다. 값은 docs/reference/scale-skewer-prototype.html 의 :root 를 따른다.
8. 한 단계에서는 그 단계의 범위만 한다. 범위 밖의 개선은 제안만 하고 손대지 않는다.
9. 새 패키지는 이유를 말하고 허락을 받은 뒤 추가한다.
10. 설치된 Next.js 버전의 공식 문서를 확인하고 그 버전의 방식으로 쓴다.

## 확인 명령
- npm run check : 타입 검사 + 린트 + 단위 테스트
- npm run e2e   : 화면 자동 점검
- npm run build : 정적 내보내기

## 작업 순서
계획을 먼저 보여 준다 → 승인을 받는다 → 구현한다 → npm run check 를 돌린다 → 보고한다.
보고에는 만든 것, 확인한 것, 확인하지 못한 것, 사람이 직접 볼 것을 적는다.
커밋은 단계마다 한 번, 한국어 한 줄 요약으로 한다.
````

## 2. 필수 단계 (1~16)

### 1단계 — 프로젝트 뼈대

**목표.** 빈 화면 하나가 뜨고 검사 명령 세 가지가 통과한다.

**프롬프트**

````text
[1단계 — 프로젝트 뼈대]

먼저 docs/음계꼬치구이_기획서.md 의 0장, 1장, 12장과
docs/음계꼬치구이_프롬프트설계서.md 의 "1. CLAUDE.md 초안"을 읽는다.

목표: 빈 화면 하나가 뜨고, 검사 명령 세 가지가 통과하는 뼈대.

할 일
1. 이 폴더에 Next.js 최신 안정판 프로젝트를 만든다(App Router, TypeScript, Tailwind CSS, src 폴더).
   docs 폴더는 건드리지 않는다. 설치된 버전의 공식 문서를 확인하고 그 버전의 방식으로 설정한다.
2. 서버 기능 없이 파일만으로 돌아가는 정적 내보내기로 설정한다.
3. TypeScript 는 엄격 모드로 하고 noUncheckedIndexedAccess 를 켠다.
4. Vitest(단위 테스트)와 Playwright(화면 테스트)를 넣는다.
   Playwright 는 Chromium 과 WebKit, 화면 크기 360×640, 390×844, 1024×768 로 설정한다.
5. package.json 에 check(타입 검사 + 린트 + 단위 테스트), e2e, build 명령을 만든다.
6. 기획서 12장의 폴더를 만든다(내용은 비워 둔다).
7. 프롬프트 설계서의 "CLAUDE.md 초안" 안의 내용을 그대로 CLAUDE.md 로 저장한다.
8. 홈 화면에는 "음계 꼬치구이" 제목만 보이게 한다. 문서 언어는 ko 로 한다.
9. .gitignore 와 README(실행 방법 다섯 줄 안쪽)를 만든다.
10. git 저장소를 만들고 첫 커밋을 한다.

하지 않는 것: 게임 기능, 꾸미기, 배포.

완료 기준
- npm run check, npm run e2e(제목이 보이는지 한 가지), npm run build 가 모두 통과한다.

끝나면 만든 것, 확인한 것, 확인하지 못한 것, 내가 직접 볼 것을 나눠서 보고한다.
````

### 3단계 — 주문 상태와 안내 문구

**목표.** 화면 없이 "건반을 눌렀더니 무슨 일이 일어나는지"를 계산하고, 입문 대본이 테스트로 돌아간다.

**프롬프트**

````text
[3단계 — 주문 상태와 안내 문구]

먼저 CLAUDE.md, 기획서 4장, 5-3절, 5-6절, 6-3절, 8장을 읽는다.
docs/reference/scale-skewer-prototype.html 의 스크립트에서 "4. 이름과 문장"과 "7. 진행" 부분을 읽는다(동작의 본보기).

목표: 배우기 주문의 상태와 동작을 순수 함수로 만들고, 문구를 한곳에 모은다.

할 일
1. src/game/order/ 에 기획서 6-3절의 OrderState 와 동작을 만든다. 이번 단계는 kind 가 'learn' 인 주문만 한다.
   - startOrder(scaleId, kind, seed, options) → 상태
   - tapKey(state, keyIndex), tapSlot(state, slot), askHint(state), bake(state), serve(state)
   - 각 동작은 { state, effects } 를 돌려준다. effects 는 화면에 알릴 일의 목록이다:
     문구(번호와 값), 들려줄 음(음높이 번호와 간격), 강조할 자리·건반, 반짝일 건반, 묶어 보일 두 건반, 흔들 자리, 굽는 소리, 조표로 모으기.
   - options.guide 는 'full'(입문 주문 1), 'intro2'(입문 주문 2), 'light'(보통) 가운데 하나다.
2. 판정과 힌트는 엔진의 place, diagnose, hint 만 쓴다. 규칙은 R-20~R-24, R-30.
   - 맞게 꽂힌 자리는 잠긴다. tapSlot 은 그 음을 다시 들려주는 effects 만 낸다.
   - 같은 자리에서 틀릴 때마다, 힌트를 누를 때마다 힌트 단계가 1씩 오른다(최대 3). 자리가 바뀌면 0.
   - 소리와 강조는 기획서 8-3절의 표를 따른다.
3. src/lib/strings.ts 에 기획서 8-2절의 문구를 번호(T-01 … T-70)로 모은다.
   문구는 글자 덩어리, 음 이름 덩어리, 온음·반음 알약 덩어리의 목록으로 돌려준다(화면이 덩어리마다 다르게 그린다).
4. src/lib/josa.ts 에 R-62 의 조사 규칙을 만든다(을/를, 은/는, 와/과, 로/으로, 라고/이라고).
5. 음 이름 덩어리는 표기 설정(R-60)에 따라 한글, 영어, 한글+영어로 바뀐다.

테스트 (Vitest)
- 입문 대본(기획서 8-4절): 주문 1을 정답 순서로 눌렀을 때 문구 번호가
  T-01 → T-10 → T-10 → T-11 → T-10 → T-10 → T-10 → T-12 → T-16 순서로 나온다. 굽기 뒤 T-30.
- 주문 2(F)에서 4번째 자리에 건반 6(B)을 누르면 T-20, 다시 틀리면 T-22, 또 틀리면 T-23 과 정답 음.
  그 뒤 건반 5(B♭)를 누르면 T-15.
- 8번째 자리에 건반 0 을 눌러도 높은 으뜸음(음높이 번호 = 으뜸음 + 12)이 꽂힌다.
- 영어 표기의 글자 예:
  "A에서 B까지는 온음이에요. 여기는 반음 자리! 반음은 바로 옆 건반이에요."
  "4번째 음은 B♭! A 다음 글자 B를 써서 B♭이라고 해요. (A♯과 같은 건반)"
````

## 5. 막혔을 때 쓰는 도움 프롬프트

**H-1. 검사가 통과하지 않을 때**

````text
npm run check (또는 e2e, build) 가 통과하지 않는다. 고치기 전에 먼저 알려 줘.
1) 무엇이 실패했는지 쉬운 말로 2) 원인으로 보이는 것 3) 고치는 방법과 그 영향.
테스트를 지우거나 느슨하게 바꾸는 방법은 쓰지 않는다.
````

**H-2. 엔진이 검증 자료와 맞지 않을 때**

````text
검증 자료와 맞지 않는 항목이 있다. docs/reference 의 파일은 고치지 않는다.
맞지 않는 항목 3개를 골라 "넣은 값, 나온 값, 정답, 해당 규칙 번호(R-xx)"를 표로 보여 주고,
src/game 의 어느 부분이 규칙과 다른지 찾아 고쳐 줘. 고친 뒤 전체 대조 결과를 붙여 줘.
````

**H-3. 화면이 넘치거나 겹치거나 글자가 잘릴 때**

````text
[기기 또는 화면 크기]에서 [어느 화면의 무엇]이 [넘친다 / 겹친다 / 잘린다].
그 크기로 스크린샷을 찍어 확인하고, 기획서 7-1·7-2절의 크기 기준 안에서 고쳐 줘.
글자를 지금보다 작게 하지는 않는다. 고친 뒤 360×640, 390×844, 1024×768 스크린샷을 붙여 줘.
````

````text
[기종, 브라우저]에서 소리가 나지 않는다. 무음 설정은 [켬 / 끔], 볼륨은 [ ], 이어폰은 [ ].
기획서 9장을 읽고 원인으로 볼 수 있는 것을 가능성이 큰 순서로 알려 줘.
내가 폰에서 해 볼 확인 방법을 하나씩 안내하고, 결과를 알려 주면 그에 맞게 고쳐 줘.
````

````text
이번 단계의 범위가 아닌 것까지 바뀌었다. 바뀐 파일 목록과 각 파일을 바꾼 이유를 표로 보여 줘.
이번 단계의 "하지 않는 것"에 해당하는 변경은 되돌리고, 필요하다고 생각한 것은 제안으로만 남겨 줘.
````
